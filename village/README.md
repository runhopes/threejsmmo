# Taşkale — castle village starter zone

Procedural (three.js r128, no external models or images) fortified starter town that replaces the old grid arena in
`index.html`. Everything is built at load time from code in this folder (~3 s on a Radeon 610M iGPU).

## Files

| File | Role |
|---|---|
| `core.js` | `CONFIG`, seeded RNG / noise, **Builder** (static geometry merged per material per 32 m chunk), **Instancer** (chunked `InstancedMesh`), **Collision** (2D OBB / circles with heights), **NavGrid** (0.5 m, A* + string pulling), **Registry** |
| `materials.js` | Procedural canvas textures + normal maps, shared materials, occluder dithering (roof fade), GPU banner sway |
| `terrain.js` | TerrainBuilder (flat walkable ground, hills beyond), RoadBuilder (splat painter: cobbles / earth / flagstones / wear / contact shadows), PlazaBuilder (engraved octagon) |
| `architecture.js` | MedievalHouseBuilder kit (walls with real openings, windows, doors, timber framing, gable / half-hip / hip roofs, chimneys, dormers), KeepBuilder, banners |
| `fortifications.js` | WallBuilder (bay-by-bay curtain walls), TowerBuilder (corner drums, watchtowers), GatehouseBuilder |
| `props.js` | PropFactory (wagon, well, stalls, forge set, racks, butts, fences…) + VegetationBuilder templates (instanced trees, bushes, grass) |
| `scene.js` | CastleVillageScene: district layout, roads, NPC points, assembly, runtime (fade, clutter LOD, shadow snapping), debug overlay |
| `integrate.js` | `Village.forGame()` glue used by `index.html` |
| `forest.js` | Mystic giant forest: giant trees (buttressed trunk, roots, limbs, painted leaf-card crowns), far LOD, the colossal tree north of the keep, ferns / glowing mushrooms / moss logs / boulders, card crowns for the village trees |
| `atmosphere.js` | Fog chunk patch (tinted depth fog + ground-mist height fog with drifting pockets), painted sky, light grade, fireflies, god rays, vignette |
| `phtex.js` | Poly Haven CC0 textures (bark, forest floor, meadow, mossy rock), painterly-filtered, generated by `tools/packvtex.mjs` |

## Mystic forest atmosphere (forest.js + atmosphere.js, 2026-11-05)

Goal: a relit "Classic+ MMO" look (reference screenshots analysed): tinted depth fog that eats the distance, ground-mist
pockets, warm low sun against blue-teal shade, god rays, giant trees, dappled light. `?atmo=0` = the previous look.
The Poly Haven textures are the only images; every model is still procedural.

* **Giant trees** are instanced templates (`giant0/1`, `giantFar`, `titan`). Crowns are alpha-tested leaf cards with
  spherical normals on a **Lambert** material (per-vertex light, no shadow receive). The cards do NOT cast shadows: a
  crown-wide horizontal quad with the `dapple` silhouette (material `shadowOnly`, never reaches the screen) casts the
  dappled shadow. Card shadows alone cost ~30 % of a frame on the Radeon 610M, so keep it that way.
* Under every crown `populate()` paints canopy AO and a **forest-floor mask** (Splat channel `forest`, packed into the
  AO texture's blue channel). The terrain shader blends the Poly Haven meadow / forest floor with it, which also keeps
  the ground dark under crowns outside the shadow map.
* Trunks, buttress lobes, roots and moss logs get colliders. Camp clearings: `F.CLEARINGS` must match `integrate.js` SITES.
* The fog patch rewrites `ShaderChunk.fog_*` for built-in materials (no custom shader uses them) and shares its
  uniforms through ShaderLib with a self-returning `clone()`. Tune colours / densities in `Atmosphere.P`.
* Additive shaders (fireflies, god rays) output non-premultiplied colour: three's AdditiveBlending is SRC_ALPHA, ONE.
* The sky is drawn after the opaque world at the far plane (early-z), because it runs a cloud fbm.
* Check with `node tools/atmoshot.mjs <out> grove,camp,meadow [--pitch=12 --dist=18] [--q=atmo=0]`. The low pitch is
  the horizon view players use; always A/B fps against `?atmo=0` in the same run.

## Layout (meters; +x east, +z south; the game camera looks north)

Interior 150 × 150 m (`?vsize=` 120–220 rescales district anchors; buildings keep real size). Spawn plaza at the
origin; keep + courtyard north; south gatehouse (6 m passage) with the road forking to the hunting grounds; market +
tavern east; healer, 10 houses (5 variants), well courtyard west / north-west / north-east; blacksmith on the south
road; training yard south-east (4 dummies, 3 archery lanes shooting north); stable + storage courtyard south-west.

## Game integration (`index.html`)

* Default world is the village. `?world=arena` = the old grid arena (tools that depend on the old layout).
* Spawns: class selection → `plaza` (0, 7.5, facing north). `?cls=` quick start → `training` (dummy #1 keeps the old
  +2 / −3.8 offset). Override with `?spawn=plaza|training|archery|gate_inner|gate_outer`.
* `` ` `` (backquote) or `?vdebug=1`: colliders, nav grid, spawns, NPC placement points, exits, world bounds.
* Movement: `VW.collide()` after every hero update; right / left click ground moves follow `VW.findPath()`.
* Arrows / fireballs stop on walls, roofs, trunks, posts (`VW.projectileHit`). Blink is clamped (`VW.clampMove`).
* Creature camps keep their species / counts / radii but are re-sited outside the south gate (`VW.creatureZones`).

## Registry (`VW.registry`)

`spawns`, `npcs` (blacksmith, merchant ×6, healer, quest_giver, trainer, innkeeper, steward, stablehand, gardener,
woodcutter, guards ×15 incl. elevated tower / gate posts with `position.y`), `transitions` (three road exits),
`dummies`, `targets`, `waypoint`. NPCs are placement points only — no NPC logic or quests are implemented.

## Constraints worth knowing

* **Walkable ground is exactly y = 0.** The hero's foot IK plants feet at world y = 0, so elevation lives only where
  nobody walks (hills beyond the boundary, plinths, stairs with colliders, raised beds).
* Static geometry is merged; to change a building, edit its generator and reload — there are no per-building meshes.
* Dev tools: `village.html` (free camera viewer), `tools/villageshot.mjs`, `tools/villageplay.mjs` (real game input),
  `tools/villagenav.mjs` (reachability audit), `tools/villageperf.mjs` (frame-cost breakdown).
